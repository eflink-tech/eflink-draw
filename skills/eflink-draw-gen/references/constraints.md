# 渲染约束与已知坑（生成 spec 前必读）

这些是编辑器渲染管线的硬约束，违反会产生"缩略图正常但编辑器不对"或反之的问题。

## 1. 连线画在所有形状下方（Konva 独立 Layer）

编辑器连线渲染在独立图层、位于**全部形状之下**。任何不透明形状都会盖住穿过它的连线段。

- **禁止**用整片不透明底框/背景矩形（曾踩坑：泳道图用白底框模拟泳道，连线全被盖住）
- 布局时保证连线只经过空白区域，不横穿其他形状；泳道用原生 `swimlaneV`（fillStyle=none 透明，不挡线）
- 两条连线回环方向相反时会重叠——错开锚点或 side

## 2. 端点角度是内向角约定

转换器已处理（sidePoint 输出 π/2、π、3π/2、0）。若手工改 DocumentData：
top=π/2、right=π、bottom=3π/2、left=0（指向图形中心、归一化 [0,2π)）。
外向角（top=-π/2）会让编辑器重路由时判错方向。注意 eflink-frontend `helpers.ts` 的
`buildDraw` 存的是外向角，是已知偏差，别照抄。

## 2b. 椭圆（round）参与的连线是直线

ER 图属性、中心辐射、思维导图气泡这类 round 节点的连线，原图一律是**直线**；
转换器对任一端为 round 的连线自动存空 `points`（直线），不走正交路由——正交路由会把
斜向线掰成 Z 形弯折、把近垂直线掰出小台阶。**spec 里不用做任何事**，照常写 from/to
（也无需 fromSide/toSide，转换器按位置推断）；流程图矩形/菱形之间的连线仍是正交路由。
用户报告过正交弯折不美观（#060 用户-订单 ER），别回退此规则。

### 2b-2. 树式路由（子节点在正上/正下方时自动）

WBS/组织架构/层级树这类"父上子下"的连线，转换器自动走**树式路由**：父底(顶)中点 →
父子间隙中位横线 → 子顶(底)中点，贴.ProcessOn 原图的树连接画法（用户反馈过
inferSides 主轴推断在宽浅树上会"右出左进"横穿全图，#696 WBS）。spec 照常只写
from/to 即可；**仅在显式写 fromSide/toSide 时才按指定的边走旧正交路由**——树图不要写 side。

## 2c. 类图用原生 cls，别用矩形拼装

UML 类图的三段式类框（类名/属性/操作）用 `native:'cls'`（见 spec-format.md），
转换器还会**自动兜底合并**：同宽贴合堆叠的"短标题矩形 + 两个多行正文矩形"会被合并成
一个 cls 节点（正文连线端点自动重映射）。用户报告过矩形拼装版不美观（#064 UML类图，
dbId 876），别再按"三段矩形拼装"退化规则出类图；表格/说明块被合并成 cls 视觉上也
更接近原图（标题栏+分隔线+左对齐文字），无需规避。

## 2d. 架构图的层带/分组背景必须保留

系统架构图、分层图里的**大面积底色层带、虚线分组框、组名标签是骨架不是装饰**，
节点数超了优先裁图标/插画，也不能裁它们（用户反馈过丢失背景很难看，#161）：

- 底色层带：大圆角矩形 `"z": 4`（低图层），内容节点 z≥10 叠在上面；**带内不放连线时放心用实色填充**，
  渲染按 zindex 分层，内容不会被带盖住。层与层之间的大箭头画在带间空隙
- 虚线分组框（WEB/APP/管理系统这类）：矩形 `"fill": "none"`（透明不挡线）+ `"lineStyle": "dashed"`，
  组名用小矩形标签放在框内左上角
- 节点上限：一般 80；**架构图/分层图/拓扑图可到 150**——背景带+分组框+内容全保留，
  只裁剪设备图标、人物插画这类纯装饰图形
- **深色画布原图的画法**（用户反馈过黑白反转，#215/#288）：原图黑/深底但内容面板是
  白底+彩色虚线边框时，**内容面板必须画成白底（或 fill:"none"+虚线边框），禁止画成深色
  大块**；大面积矩形（w≥300）填充 luma<90 仅限原图本身就是深色面板/深色画布整体背景，
  画布底色用 page 层表达、不要摊成大矩形；判断不准就按白底+虚线框出，风格更接近原图
- **设备/云产品必须用图标形状**（用户反馈过矩形凑图标很丑，#1851/#1866/#1886）：
  原图里的服务器、数据库、防火墙、云产品（ECS/RDS/OSS/SLB/CDN/WAF/VPC…）、网络设备
  一律用 `native` 图标（查 net-icons.md：阿里云 ali_*/ali2_*、网络设备 topo_*、aws_*/aws4_*/azure），
  基础件用 cloud（云）/directData（数据库圆柱）/internalStorage（存储）；
  层间大数据流箭头用 singleUp/DownArrow 等箭头形状；**禁止用普通矩形+文字模拟图标**
  （抽象模块框才是矩形）；图标配上 text 即下方标签，无需另画文字框
- **专业图优先用新图形库**：电气原理图/电路图用 `elec_*`（电阻、电容、二极管、逻辑门、波形等
  按元件原貌排列，不要用矩形+文字代替）；机房/机柜立面图用 `rack_*`（按 U 高比例缩放，
  同柜设备宽度一致、上下紧贴）；Web/App 原型用 `mk_*`；人物/医疗/交通等插图用 `signs_*`。
  这些图标名都是 `<分类>_<英文原名>`，可在 net-icons.md 按分类 grep

## 3. 泳道（swimlaneV/H）静态渲染用存储 path

编辑器画布从元素存储的 `path` 渲染泳道（拖分界线时才重建）。所以 **laneCount 与存储 path
的分隔线数必须一致**（n 泳道 = n-1 条竖分隔线）——转换器的 native 构建已保证，手工改
DocumentData 时注意。泳道头格背景色存在实例字段 `laneHeadColors`，title 色 `titleColor`。

## 4. 时序消息（seq）端点

- from/to 的 x 必须在条缘（dir=1 → 条右缘 x+w；dir=-1 → 条左缘 x），y 恒等于 seq.y
- `points` 恒为空数组；移动激活条后编辑器按 `seq` 元数据重算
- 自消息（回环）暂不支持生成（编辑器有特殊回环几何），需要时退化为两条消息或手工调整

## 5. 折点去重

正交路由在锚点几乎对齐时会产生零长段，转换器已去重（>0.5px 保留）。手工构造 points 时同样注意。

## 6. 预览双管线差异

- **编辑器**：Konva + shapePaint，按存储 path 渲染（权威）
- **模板卡片/预览弹窗/admin 审核**：eflink-frontend `DocThumb.tsx` 的 DrawThumb SVG，
  已升级为同样按存储 path + 表达式求值渲染（2026-09-29），两管线几何一致
- 生成后的验收以编辑器打开为准；SVG 预览（convert 产物 .svg）用于快速人工核对

## 7. 文字与颜色

- fill 用 "r,g,b" 十进制串；深色（luma<150）自动白字、加粗；textColor 可覆盖
- **换行**：编辑器 textDisplay 层 pre-wrap 自动换行；转换器 SVG 预览与前端 DrawThumb 均内置
  CJK 感知换行 + 超高缩字（最小 8px）+ 截断省略号，长文本无需在 spec 里手工插 \n
  （显式 \n 仍保留为强制段落）。但过长的文本缩字后可读性差——spec 里仍应给足宽度
  （中文 13px ≈ 每字 13px 宽），或精简文案
- **竖排文字（原图窄高框）**：原图里组织架构/功能结构的叶节点常是"窄高矩形 + 逐字竖排标签"
  （如 62×280 的"学生评价"）。spec 照抄原图的窄高尺寸即可，**转换器会自动竖排**：
  h≥w×1.4、文字以 CJK 为主、无换行、且"每字一行"竖排放得下（字数 ≤ h/(fontSize×1.2)）时，
  text 自动转为逐字换行。要保横排就给宽扁尺寸或自己插 \n；不要把窄高框抄成宽扁框
- 连线标签文字颜色固定深灰（DrawLinkSpec 无 textColor 字段）
